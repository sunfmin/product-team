# test-speed-review — skill-spec

- name: test-speed-review
- description: make a test suite / CI / gate fast without weakening what it proves; measure, find overhead, pair each saving with a proof check, add a time guard; read-only until the user picks.
- should_fire:
  - "our CI takes 25 minutes, how do we make the tests faster?"
  - "测试太慢了，帮我看看时间都花在哪"
  - "the pre-merge gate got slow this month, find where the time goes and stop it creeping back"
  - "which of our tests are the slowest and what can we do about them without deleting coverage"
  - "speed up the gate"
- decoys:
  - "where should we add property-based tests?" (test-rigor-review)
  - "this API endpoint is slow in production, profile it" (product perf)
  - "TestFoo fails intermittently on CI, find out why" (diagnosing-bugs)
  - "write tests for the parser module" (tdd)
  - "why is my Mac's CPU so hot?" (whats-hot)
- examples: "/test-speed-review the gate", "测试怎么跑快点但不能删测试"
- needs: the project's own test runner and its timing output; mutation tool via test-rigor-review
- functional_test: fixture repo with (a) a per-test rebuilt artifact, (b) sleep-as-wait, (c) per-test DB-ish setup. Success = report opens with a measured baseline + split, finds all three as S findings each with seconds and a proof check, flags missing guard as G ranked first, and edits no file.
- target: dedicated repo sunfmin/test-speed-review
- visibility: public
